# FRONTEND.md — the `web/` frontend

The Camea frontend: TypeScript + React + Vite, in `web/`. It replaces the archived vanilla-JS app
(`archive/app-v1/frontend/`). The backend (`src/camea/`) is **frozen** — the frontend never edits it
and never hand-writes a type the backend owns.

> **Read `docs/BEHAVIOUR.md` before building UI.** It is the testable contract (~44 numbered rulings)
> extracted from v1. This document is only about the *scaffold and toolchain*.

---

## The stack, and why each piece

| piece | choice | why |
|---|---|---|
| bundler / dev server | **Vite 6** | Fast HMR; content-hashed production filenames satisfy BEHAVIOUR R32 (a new `index.html` must never load a stale asset). One config drives dev, build and unit tests. |
| UI | **React 18** (strict TS) | The team's target. `<StrictMode>` on. |
| router | **react-router-dom 6** | Small, standard nested routes that map onto *shell → feature → step*. No framework lock-in. |
| state | **Zustand 5** | The Sweep loop is a 60 fps canvas driven by keys, with a prefetch + key handler partly **outside** React (BEHAVIOUR R21/R33). Zustand gives selector subscriptions (a cursor tick must not re-render the rails — R20's ~6 ms budget) and `getState()`/`setState()` access with no Provider. See `src/store/sweepStore.ts`. |
| styling | **CSS Modules + CSS custom properties** | A bespoke *instrument* UI (a radiologist reading room), not a utility-class marketing page. Tokens live in `src/styles/tokens.css` (dark-first, theme-aware); component styles are colocated `*.module.css`, hand-tuned so the canvas stays the hero. No component kit (no MUI/Chakra) — every control is built here. |
| API types | **openapi-typescript** → `src/api/schema.d.ts` | HARD RULE 2: the contract is **generated, never hand-written**, from `docs/openapi.json`. |
| API client | **openapi-fetch** (`src/api/client.ts`) | ~6 kB typed fetch wrapper; path, params, body and response all checked against `paths`. |
| unit tests | **Vitest 3** (+ jsdom, Testing Library) | Same config as Vite; runs on a clean clone with no data. |
| e2e | **Playwright** (chromium) | Drives the real app against the real backend + the committed fixture. |
| lint / format | **ESLint 9** (flat config, typescript-eslint) + **Prettier 3** | |

## The two-terminal dev loop

The frontend talks to the backend over `/api` and `/openapi.json`, which the Vite dev server proxies
to the FastAPI process (loopback only — the backend refuses to bind anything but `127.0.0.1`).

**Terminal 1 — the backend (headless), pointed at a dataset root:**

```bash
uv run camea --headless --port 8000 --open <a-folder-that-contains-datasets>
```

> ⚠️ **There is no `--data-dir` flag.** The app carries no dataset knowledge (HARD RULE 3). `--open`
> puts a path in `settings.recent_datasets` — *"start me near here"* — and nothing else. It opens no
> dataset and scans nothing. To use the committed fixture, point it at `tests/fixtures` (the dataset
> is `synthetic/` beneath it).
>
> ⭐ **There is no root registry (2026-07-25 — BEHAVIOUR R42).** `GET /api/datasets` and
> `POST /api/datasets/scan` are gone: the home screen is the **project manager**, and a new project
> asks outright *where the data comes from* and *where to save*. `POST /api/datasets/at` answers
> "what is in THIS folder" and remembers nothing.

**Terminal 2 — the frontend:**

```bash
cd web
npm install
npm run dev        # http://127.0.0.1:5173  (proxies /api + /openapi.json to :8000)
```

Override the proxy target with `VITE_BACKEND=http://127.0.0.1:<port>` if the backend is elsewhere.
(Vite binds `127.0.0.1` explicitly — its default `localhost` resolves to IPv6 `[::1]` on Windows,
which would not answer the IPv4 backend, proxy and test URLs.)

## The generated API contract

`docs/openapi.json` (44 paths, 51 ops, 103 schemas) is the source of truth. It is itself dumped from
the backend: `create_app().openapi()`.

```bash
npm run gen:api     # openapi-typescript docs/openapi.json -> src/api/schema.d.ts
npm run check:api   # CI GUARD — fails if schema.d.ts has drifted from the LIVE backend
```

`check:api` (`scripts/check-schema.mjs`) does not trust the committed JSON: it dumps a **fresh**
schema straight from the backend (`uv run python …`), regenerates types from it, and diffs against the
committed `src/api/schema.d.ts`. So it catches drift in both directions — a hand-edited `schema.d.ts`
**and** a backend change nobody regenerated. On mismatch it prints the 3-step fix (refresh
`docs/openapi.json`, `npm run gen:api`, commit). `schema.d.ts` is committed so CI has something to diff.

## The committed synthetic fixture

`tests/fixtures/synthetic/` is a **real** vscope acquisition on disk — it is what lets Playwright and
CI run without the 35 GB mirror. It is generated by `tests/fixtures/make_synthetic.py`, which
**reuses** the backend's own generator (`tests/api/conftest.py::_write_dataset`, loaded by path) with
a trimmed run:

```bash
uv run python tests/fixtures/make_synthetic.py   # deterministic — re-running leaves the git diff empty
```

- **12 readable frames**: a 10-tile serpentine run (trials **11–20**, 512×512, 128 px overlap step
  with **known top-left offsets** — the matcher truth), one stray snapshot (trial 5, a second block),
  and one **off-shape** frame (trial 9, 512×128 — real data the mosaic shape-gate must refuse by shape,
  not by number). Plus non-snapshot trials 1–2 in `log.txt`.
- Exercises: block selection (longest block = 11–20), the 512×512 gate, the conditional 180° flip
  (`ax=-1 ay=-1`, bytes written pre-flipped), and the timing-split detector (a planted 40 s pause at
  16→17, found from the timestamps alone → split **16**).
- **Size: ~5.6 MiB.** ⚠️ This exceeds the ~1 MB target in the brief. A committed 512×512 `uint16` raw
  frame is a fixed **0.5 MiB**, so 9–12 real mosaic tiles cannot fit in ~1 MB; the lever pulled was
  frame *count* (trimmed from the API suite's 20-tile, ~12 MiB set). Dropping below 512×512 would make
  the mosaic feature reject every tile, defeating "known placements".
- `.gitignore` re-includes it via `!/tests/fixtures/**` (verified: `git check-ignore` reports the
  `.dat`/`.xml`/`log.txt` as committable).

## Testing

```bash
npm run test         # vitest (unit) — src/**/*.{test,spec}.{ts,tsx}
npm run e2e:install  # one-time: playwright install chromium
npm run e2e          # playwright — boots the backend (headless, at tests/fixtures) AND the vite
                     # dev server itself, then drives the smoke test. See playwright.config.ts.
```

The smoke test (`e2e/smoke.spec.ts`) loads the shell, asserts the project manager renders, creates a
project on the fixture (`synthetic`, 12 snapshots, 512×512), and opens it into the mosaic feature at
`/project/:id`. Vitest and Playwright do
not fight over `*.spec.ts`: Vitest is scoped to `src/`, Playwright to `e2e/`.

## CI (`.github/workflows/ci.yml`)

Runs on every **push** and **pull_request**, on any branch. The one rule the whole repo is built
on holds here too: **CI proves the app without the private data.** It runs on a stock GitHub runner
with **no 35 GB mirror and no GPU** — the only dataset it touches is the committed ~5.6 MB synthetic
fixture at `tests/fixtures/synthetic/`. Four jobs, in parallel:

| job | toolchain | does |
|---|---|---|
| **backend** | Python 3.12 + uv | `uv sync` (no `gpu` extra) → `ruff check` → `uv run pytest -q` (fast suite) → `mypy` *(advisory, non-blocking)* |
| **frontend** | Node 22 | `npm ci` → `npm run build` (tsc + vite) → `npm run lint` → `npm run test` (vitest) |
| **api-drift** | Node 22 + uv | `npm run check:api` — dumps the live OpenAPI from the backend and diffs the committed `schema.d.ts` (HARD RULE 4). Needs both toolchains, so it is its own job. |
| **e2e** | Node 22 + uv | `npx playwright install --with-deps chromium` → `npx playwright test --project=fast` |

**What CI deliberately does NOT run** (and why):

- **The 312/312 solver guard** (`tests/slow/test_solver_312.py`) — needs the private mirror + a GPU.
  It is `@slow`, and pyproject's `addopts = -m 'not slow'` deselects it before its fixtures are ever
  built, so `uv run pytest` in CI never touches it. Runs locally / nightly.
- **The Playwright `@slow` specs** — they drive a real t33 GPU solver build. The e2e job runs only
  the **`fast`** Playwright project (defined with `grepInvert: /@slow/`), so the slow build specs are
  excluded on a GPU-less runner. Run them locally with `npm run e2e`.
- **The `gpu` extra** (`cupy-cuda12x[ctk]`) — never installed in CI; there is no CUDA runtime. CI
  exercises the engine's CPU/NumPy path.

Caching: uv keyed on `uv.lock` (`astral-sh/setup-uv` `enable-cache`); npm keyed on
`web/package-lock.json` (`actions/setup-node` `cache: npm`).
